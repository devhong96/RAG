# 임베딩 계보 — Word2Vec에서 현대 임베딩 모델까지

> 학습 위치: [전체 문서 지도](../README.md) · 이전: [벡터DB](../01-basics/vector-db.md) · 실습 코드: [`vector-math.ts`](../../src/lib/vector-math.ts)

이 문서는 [벡터 DB와 임베딩](../01-basics/vector-db.md) 1장을 읽은 뒤 보는 것이 좋다. 처음에는 모델 이름을 외우기보다 **표현 단위가 단어에서 문장으로, 고정 벡터에서 문맥 벡터로 어떻게 바뀌었는지**를 따라간다.

## 1. 왜 임베딩이 필요한가

컴퓨터가 문자열 그대로 비교하면 `자동차`와 `차량`은 다른 값이다. 임베딩은 항목을 고정 길이 벡터로 바꾸고, 함께 쓰이거나 의미가 비슷한 항목이 가까워지도록 학습한다. 이후 분류·군집·추천·검색은 같은 벡터 공간에서 거리 문제로 바뀐다.

## 2. Word2Vec — 주변 단어로 단어를 학습한다

Word2Vec은 문장 전체의 뜻을 직접 저장하지 않는다. 큰 말뭉치에서 **어떤 단어가 어떤 주변 단어와 함께 나타나는가**를 예측하면서 단어별 벡터를 학습한다.

- CBOW: 주변 단어들로 가운데 단어를 맞힌다.
- Skip-gram: 가운데 단어로 주변 단어들을 맞힌다.
- Negative sampling: 모든 단어를 매번 비교하지 않고, 정답과 소수의 오답 후보만 비교해 학습 비용을 줄인다.

유명한 `왕 - 남자 + 여자 ≈ 여왕`은 일부 관계가 벡터 방향으로 나타날 수 있음을 보여준다. 항상 성립하는 논리 규칙은 아니다. 말뭉치의 편향과 빈도, 전처리, 모델 설정에 따라 결과가 달라진다.

Word2Vec의 근본 한계는 **단어 하나에 벡터가 하나뿐**이라는 점이다. `은행`이 금융기관이어도 강둑이어도 같은 좌표를 쓴다.

## 3. Doc2Vec — 문서 ID도 함께 학습한다

Doc2Vec은 Word2Vec 학습에 문단이나 문서 ID를 나타내는 벡터를 추가한다.

- PV-DM: 문서 벡터와 주변 단어를 이용해 다음 단어를 예측한다.
- PV-DBOW: 문서 벡터만으로 문서에 등장하는 단어를 예측한다.

문서 전체를 고정 길이로 표현할 수 있지만, 새 문서 벡터를 얻기 위한 추가 추론이 필요하고 긴 문서의 세부 의미가 하나의 벡터에 뭉개질 수 있다.

## 4. 트랜스포머가 바꾼 것

트랜스포머는 셀프 어텐션으로 문장 안의 다른 토큰을 함께 본다. 그래서 같은 `은행`도 문맥에 따라 서로 다른 토큰 벡터가 된다. 문장 임베딩 모델은 이 문맥 벡터들을 pooling해 검색에 쓸 하나의 벡터를 만든다.

생성 LLM의 내부 토큰 임베딩을 그대로 벡터 검색에 쓰면 안 된다. 생성 모델은 다음 토큰 예측에 맞춰졌고, 검색 모델은 관련 문장 쌍을 가깝게 만드는 대조 학습에 맞춰졌다. 이 저장소가 생성 모델과 `bge-m3` 임베딩 모델을 분리하는 이유다.

## 5. 임베딩 계층과 제로샷

임베딩 계층은 토큰 ID를 초기 벡터로 바꾸는 조회 테이블이다. 그 뒤 트랜스포머 층을 지나며 문맥 표현이 만들어진다. 제로샷 능력은 임베딩 계층 하나에서 생기는 것이 아니라, 대규모 사전학습으로 만들어진 전체 모델 표현과 학습 목표에서 나온다. 따라서 “임베딩 계층만 있으면 제로샷이 된다”는 해석은 피해야 한다.

## 6. 벡터 연산 실습

[`src/lib/vector-math.ts`](../../src/lib/vector-math.ts)는 다음을 외부 DB 없이 실행한다.

- 내적: 두 방향의 정렬 정도
- 코사인 유사도/거리: 크기를 무시한 방향 비교
- L2 거리: 좌표 사이의 직선 거리
- 중심점 집계: 여러 벡터의 차원별 평균
- Flat Top-K: 모든 후보를 비교해 정확한 이웃 선택

벡터 산술은 벡터의 차원이 같을 때만 가능하다. 모델이 다르면 차원이 같더라도 좌표계가 다르므로 서로 더하거나 비교해서는 안 된다.

아주 작은 2차원 예제로 먼저 생각하면 쉽다.

```text
질문       q = [1.0, 0.0]
문서 A     a = [0.9, 0.1]   ← q와 방향이 거의 같다
문서 B     b = [0.0, 1.0]   ← q와 직각이다
```

코사인 유사도는 벡터의 길이보다 방향을 본다. 따라서 A가 B보다 먼저 나온다. 실제 임베딩은 2차원이 아니라 1024차원이고 각 축에 사람이 읽을 이름이 없지만, 비교 원리는 같다.

코드를 읽을 때는 다음 순서가 좋다.

1. `cosineSimilarity`에서 내적을 두 벡터 크기로 나누는 부분을 본다.
2. `cosineDistance`가 왜 `1 - similarity`인지 확인한다.
3. `topKByCosine`이 모든 후보를 계산하고 정렬하므로 왜 O(N)인지 생각한다.
4. [`core.test.ts`](../../src/lib/core.test.ts)의 `벡터 연산과 집계` 테스트를 숫자 하나씩 바꿔 실행한다.

## 7. 이 저장소의 선택

현재 구현은 Word2Vec을 새로 학습하지 않고 Ollama의 검색 특화 모델로 문장 임베딩을 생성한다. Word2Vec과 Doc2Vec은 계보와 한계를 이해하기 위한 비교 대상이고, 실제 RAG는 문맥을 반영하는 현대 임베딩 모델을 사용한다.

## 8. 학습 확인 질문

1. Word2Vec에서 같은 단어의 여러 뜻을 구분하기 어려운 이유는 무엇인가?
2. Doc2Vec이 긴 문서의 세부 내용을 하나의 벡터에 담을 때 무엇을 잃을 수 있는가?
3. 생성 LLM과 검색 임베딩 모델을 분리하는 이유는 무엇인가?
4. 차원이 모두 1024라는 이유만으로 서로 다른 모델의 벡터를 비교해도 되는가?
5. Flat 검색 결과가 ANN 평가의 기준값이 될 수 있는 이유는 무엇인가?

답을 설명할 때 모델 이름만 말하지 말고, **학습 목표·좌표계·검색 비용**이라는 세 단어를 포함해 본다.
